System Architecture

How the KPI Tracker is built and deployed: a React SPA and a Fastify + Prisma API on a single EC2 host, backed by Aurora PostgreSQL, reachable only through Cloudflare Access with Google SSO. Authorization is enforced server-side by ownership and per-View access.

01 · Overview

Topology at a glance

The browser never talks to the origin directly. Cloudflare Access authenticates the user with Google SSO at the edge and forwards the request through a Cloudflare Tunnel to the EC2 host, attaching a signed Access JWT. The origin re-verifies that JWT and fails closed. All reads and writes flow through the Fastify API, which is the only thing that touches Aurora.

03 · Authentication flow

Edge auth, origin verification

  1. User hits kpis.dealershipaccelerator.io. Cloudflare Access intercepts and requires a Google SSO login scoped to the DA org.
  2. On success, Cloudflare forwards the request through the tunnel with a signed Cf-Access-Jwt-Assertion header.
  3. A Fastify preHandler hook verifies the JWT against the Access team JWKS (checks signature, iss, and aud). On failure it returns 401. Fail closed.
  4. The verified email is resolved to a User row (auto-provisioned on first sight; seed email flagged is_admin). The user is attached to the request as req.user.
  5. Route-level authorization hooks then enforce ownership / View-access before the controller runs.
Local dev bypass. When NODE_ENV !== 'production', a DEV_LOGIN_EMAIL env var stands in for the Access JWT so the app runs without Cloudflare in front. The bypass is impossible in production because the check is gated on NODE_ENV.
04 · Component architecture

Inside the codebase

Server · Routes → Controllers → Models

  • Routes · HTTP plumbing + schema validation only. Every route declares an auth hook.
  • Controllers · business logic and authorization decisions. Never import Prisma directly.
  • Models · thin Prisma data-access layer; the only place PrismaClient is used.
  • utils/status.ts · server-only status computation, unit-tested.
  • middlewares · authenticate, requireKpiOwner, requireViewOwner, requireViewAccess.

Client · pages by domain, flat components

  • pages/ grouped by domain: Dashboard, Kpi, Views, Archived.
  • components/ flat, each co-located with its .css and .test.tsx.
  • utils/api.ts · the single API client boundary.
  • Renders status returned by the API; never recomputes it. A thin goal-rule validator gives inline form hints only.

Monorepo layout: sibling server/ and client/ (each with its own package.json), plus infra/ (Terraform) and docs/. The root runs both in dev via concurrently.

05 · Data model

Entities & relationships

Six tables. ViewKpi is the many-to-many join between Views and KPIs (with an explicit ordering); ViewAccess is the per-View share list. Ownership lives on Kpi.ownerId and View.ownerId.

Prisma schema (core)

enum Unit       { NUMBER  PERCENT  DOLLARS }
enum Comparator { EQ  GT  GTE  LT  LTE  BETWEEN }
enum Cadence    { WEEKLY  MONTHLY  QUARTERLY }

model Kpi {
  id          String    @id @default(cuid())
  name        String
  description String?
  unit        Unit
  comparator  Comparator
  goal        Decimal    // single goal, or the lower value when BETWEEN
  goalUpper   Decimal?   // the upper value; required only when comparator = BETWEEN
  cadence     Cadence
  owner       User      @relation(fields: [ownerId], references: [id])
  ownerId     String
  readings    Reading[]
  views       ViewKpi[]
  archivedAt  DateTime?
  createdAt   DateTime  @default(now())
}

model Reading {
  id           String   @id @default(cuid())
  kpi          Kpi      @relation(fields: [kpiId], references: [id], onDelete: Cascade)
  kpiId        String
  periodKey    String   // "2026-06" | "2026-W26" | "2026-Q2"
  value        Decimal
  recordedBy   User     @relation(fields: [recordedById], references: [id])
  recordedById String
  recordedAt   DateTime @default(now())
  @@unique([kpiId, periodKey])   // one value per period; re-record = upsert
}

model View {
  id          String   @id @default(cuid())
  name        String
  description String?
  owner       User     @relation(fields: [ownerId], references: [id])
  ownerId     String
  kpis        ViewKpi[]
  access      ViewAccess[]
  archivedAt  DateTime?
  createdAt   DateTime @default(now())
}

model ViewKpi {   // many-to-many join, ordered
  view     View   @relation(fields: [viewId], references: [id], onDelete: Cascade)
  viewId   String
  kpi      Kpi    @relation(fields: [kpiId], references: [id], onDelete: Cascade)
  kpiId    String
  position Int
  @@id([viewId, kpiId])
}

model ViewAccess {   // presence = Viewer; Owner is View.ownerId
  id          String   @id @default(cuid())
  view        View     @relation(fields: [viewId], references: [id], onDelete: Cascade)
  viewId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  userId      String
  grantedById String
  grantedAt   DateTime @default(now())
  @@unique([viewId, userId])
}
06 · Authorization model

Who can do what, resolved server-side

There are no global roles. Every decision reduces to ownership or membership in a View's access list. App admins are a break-glass exception. These predicates run in middleware, never inline in controllers. 

// server/src/utils/authz.ts
canAccessView(u, v)  = v.ownerId === u.id || hasGrant(v, u) || u.isAdmin
canEditView(u, v)    = v.ownerId === u.id || u.isAdmin        // rename, membership, archive
canManageAccess(u,v) = v.ownerId === u.id || u.isAdmin        // grant / revoke viewers

canAccessKpi(u, k)   = k.ownerId === u.id || u.isAdmin
                       || existsView v: canAccessView(u, v) && kpiInView(k, v)   // cascade
canEditKpi(u, k)     = k.ownerId === u.id || u.isAdmin        // edit, record value, archive

// adding a KPI to a view: owner must be able to edit the view AND access the KPI
canAddKpiToView(u, v, k) = canEditView(u, v) && canAccessKpi(u, k)

Access cascade. A viewer of a View can read every KPI in it, even KPIs owned by someone else, but can never edit them or record values. Revoking the grant removes read access to KPIs only reachable through that View.
07 · API surface

REST endpoints

All routes require a verified user. The Guard column names the authorization hook. Bodies and params are schema-validated at the route.

Sparkline payloads. List responses embed a bounded recent-readings series per KPI (e.g. the last 8 periods: { periodKey, value }) so cards can draw an inline trend without an extra request per card. Full history stays on the KPI detail endpoint. At our scale (hundreds of KPIs) the trimmed series keeps list payloads small; if a list ever grows large, the series can move behind an ?include=sparkline flag.

08 · Status computation

Server-only, one implementation

Status is derived from the latest reading and the KPI's goal rule (comparator + goal, plus goalUpper for between), with a fixed 10% band around the missed bound. It is computed once, on the server, and returned by every KPI-bearing endpoint. The client never recomputes it. 

type Status = 'green' | 'yellow' | 'red' | 'no_data';
const BAND = 0.10;

function computeStatus(comparator, goal, goalUpper, value): Status {
  if (value == null) return 'no_data';

  const meets =
    comparator === 'GTE'     ? value >= goal :
    comparator === 'GT'      ? value >  goal :
    comparator === 'LTE'     ? value <= goal :
    comparator === 'LT'      ? value <  goal :
    comparator === 'EQ'      ? value === goal :
    /* BETWEEN */             value >= goal && value <= goalUpper;
  if (meets) return 'green';

  // missed: distance past the nearest bound, as a fraction of that bound
  const bound = comparator === 'BETWEEN'
    ? (value < goal ? goal : goalUpper)
    : goal;
  const miss = Math.abs(value - bound) / Math.abs(bound);
  return miss <= BAND ? 'yellow' : 'red';
}
09 · Deployment & operations

How it ships and runs

CI (every PR)

  • Lint (ESLint) + format check (Prettier)
  • Typecheck (tsc --noEmit) on server + client
  • Unit + API tests (Vitest, isolated test DB) and E2E (Playwright)
  • Build client + server; fail the merge if anything is red

Deploy (on merge to main)

  • GitHub OIDC assumes a deploy role, no long-lived AWS keys
  • SSM Run Command pulls the release on EC2
  • prisma migrate deploy, then systemctl reload kpi-api
  • nginx serves the freshly built SPA assets
Infra is Terraform. VPC, Aurora cluster, EC2, IAM roles, and security groups live in infra/. Aurora sits in a private subnet reachable only from the API's security group. Cloudflare Access (the app + Google IdP + policy) is a documented one-time manual setup, not Terraformed.
10 · Testing & security

Confidence & posture

Testing

  • Unit · status logic, authz predicates, validators (Vitest, mocked boundaries).
  • API · every endpoint's 2xx / 4xx / 401 / 403 / 404 paths against an isolated test DB (Vitest + Supertest).
  • E2E · create KPI, group into a View, share it, verify a viewer is read-only (Playwright).
  • 85% coverage floor; authz + status approach 100%.

Security posture

  • No public inbound ports; only the outbound Cloudflare Tunnel.
  • Origin fails closed on any JWT verification error.
  • Authorization enforced in middleware on every route, no unguarded endpoints.
  • Prisma parameterizes all queries; no string-built SQL.
  • Secrets in SSM; least-privilege IAM; nightly Aurora backups.
